# Evaluation

NexusRAG has separate evaluations for retrieval, evidence-sentence detection and generated answers. The README reports the first two. Neither establishes the accuracy of answers generated by the application.

## Retrieval

The recorded runs use the full BEIR test splits: 300 SciFact queries over 5,183 abstracts and 323 NFCorpus queries over 3,633 documents. Each benchmark document is treated as one passage. This differs from the application's chunked full-document ingestion.

Search is exact cosine similarity over in-memory NumPy vectors on CPU. The application uses LanceDB for vector storage and search. Retrieval depth is 50, RRF uses `k=60`, and nDCG uses linear relevance gains. The random seed is 0.

The comparison includes MiniLM and BGE-small dense retrieval, BM25, equal-weight RRF, adaptive RRF weights and corrective retrieval. PRF means pseudo-relevance feedback: terms from retrieved passages are added to the query for one further search. The headline corrective run uses a confidence threshold of 0.55. Reranking and SPLADE are off in those runs.

| System | Embedding model | SciFact nDCG@10 | NFCorpus nDCG@10 |
| --- | --- | ---: | ---: |
| BM25 | None | 0.666 | 0.311 |
| Dense | BGE-small | 0.708 | 0.341 |
| Hybrid RRF | BGE-small | 0.704 | 0.352 |
| Adaptive weights | BGE-small | 0.703 | 0.346 |
| Corrective PRF | BGE-small | 0.703 | 0.346 |
| Dense | MiniLM | 0.648 | 0.318 |
| Hybrid RRF | MiniLM | 0.691 | 0.340 |
| Adaptive weights | MiniLM | 0.692 | 0.340 |
| Corrective PRF | MiniLM | 0.681 | 0.334 |

BGE-small means `BAAI/bge-small-en-v1.5`; MiniLM means `sentence-transformers/all-MiniLM-L6-v2`. Higher nDCG@10 is better. Combining methods did not consistently improve retrieval. With BGE-small, corrective retrieval matches the adaptive baseline to three decimal places on both datasets. The separate SciFact threshold sweep records zero triggered queries at 0.55, so it provides no evidence of a corrective benefit at that threshold. Thresholds of 0.65 and 0.70 triggered some retries and reduced test nDCG in that sweep.

The analysis uses 10,000 query bootstrap samples for 95% intervals and 10,000 paired randomizations. Reports apply Holm correction within each dataset. Individual scores, query IDs, model and dataset revisions, runtime versions and source hashes are stored in [outputs/results](../outputs/results).

The JSON result files record commit `c3a4875`, which is absent from the current history. Their source SHA-256 matches all 49 Python files at [b515aac](https://github.com/urmeo/nexus-rag/commit/b515aac7dbe6a2fc686c25f16b3f03420f624335).

## Retrieval time

These measurements use the first 120 SciFact test queries in dataset order and one CPU pass without warmup. They exclude corpus indexing and answer generation. Initial cross-encoder model loading is included in reranking time.

This experiment selects a corrective threshold on the first 250 SciFact training queries. The selected value is 0.40, separate from the headline threshold of 0.55. It triggers no retries on the SciFact test set. The reranker receives candidates from the adaptive retriever.

| System | nDCG@10 | Milliseconds per query |
| --- | ---: | ---: |
| Adaptive hybrid | 0.734 | 16.9 |
| Adaptive hybrid with corrective retrieval | 0.734 | 17.3 |
| Adaptive hybrid with cross-encoder reranking | 0.702 | 1318.9 |

The raw measurements and threshold sweep are in [corrective_scifact.json](../outputs/results/corrective_scifact.json). The timings have no repeated-run intervals and should not be treated as performance estimates for another machine.

![Recorded SciFact correction thresholds, test nDCG and retry frequency. The threshold selected on train is marked.](../assets/figures/corrective-sweep.svg)

Connecting lines join measured settings. The quality axis is zoomed. The marked threshold was selected on training data.

## Evidence-sentence detection

This task uses 188 annotated SciFact development claims and 2,031 candidate sentences, of which 18.0% are positive. Candidates come only from abstracts referenced in each claim's evidence annotations. A positive sentence is an annotated rationale that supports or contradicts the claim; the task does not search the full corpus.

| Scorer | ROC-AUC | Average precision | F1 |
| --- | ---: | ---: | ---: |
| Lexical overlap | 0.686 | 0.365 | 0.112 |
| NLI | 0.688 | 0.331 | 0.368 |
| Cross-encoder | 0.755 | 0.476 | 0.469 |

Lexical overlap uses Jaccard similarity after tokenization and stop-word removal. The NLI score adds entailment and contradiction probabilities from `cross-encoder/nli-deberta-v3-small`. The cross-encoder uses `cross-encoder/ms-marco-MiniLM-L-6-v2`.

F1 thresholds are selected on the first 120 annotated training claims from a grid of 0.30 to 0.95 in steps of 0.05. The selected thresholds are 0.30 for lexical overlap, 0.80 for NLI and 0.40 for the cross-encoder. ROC-AUC intervals use 2,000 claim-level bootstrap samples, so sentences from a sampled claim stay together.

The raw file is named [faithfulness_dev.json](../outputs/results/faithfulness_dev.json). Its `pr_auc` field stores average precision. The application's optional grounding check scores each answer sentence against every supplied source and reports the best match. It does not check whether a particular inline citation supports that sentence.

![ROC and precision-recall curves from the saved evidence-sentence scores, with random baselines.](../assets/figures/evidence-curves.svg)

The curves use all distinct saved score thresholds and group tied scores. ROC-AUC matches the recorded rank-based area. The precision-recall curve is a step plot whose area matches average precision; it is not a trapezoidal PR-area estimate.

## Run the evaluations

Install the evaluation dependencies from the repository root:

```bash
python -m pip install -e ".[eval]"
```

Run the protocol on packaged sample data:

```bash
python -m scinexusrag.eval --sample
```

Sample mode skips corrective-threshold tuning because the packaged retrieval subset has no disjoint tuning split. Uncached embedding, NLI and reranking models still need downloads. Samples are checks of the evaluation path; their scores do not replace the full runs.

Run all published evaluation protocols and render the new results:

```bash
python -m scinexusrag.eval
python -m scinexusrag.eval.report --results outputs/generated
```

Full retrieval runs require the pinned BEIR revisions and models and fail when they are unavailable. Evidence-sentence detection uses SciFact's mutable `release/latest` archive or an existing local copy. It records SHA-256 hashes of the corpus, training claims and development claims; it does not enforce a fixed dataset revision.

Fresh results go to `outputs/generated/`; the report bundle goes to `outputs/generated/paper/`. Review the new provenance and scores before publishing. Rerunning a protocol need not produce identical timing or floating-point results on a different environment.

To render the committed results without loading models:

```bash
python -m scinexusrag.eval.report
```

The report reads `outputs/results/` by default and needs the evaluation dependencies.

## Regenerate the charts

Write the three SVG charts used in the README and this guide:

```bash
python -m scinexusrag.eval.report --results outputs/results --figures assets/figures
```

This writes `retrieval-comparison.svg`, `evidence-curves.svg` and `corrective-sweep.svg` from the committed results. Text stays editable. The [pipeline diagrams](pipeline.md#implementation-and-diagrams) are maintained separately.

For a fresh run, set `--results outputs/generated` and choose a review directory with `--figures`. Check the data and conditions before replacing published charts. Identical inputs regenerate identical SVGs in the same plotting environment; fonts and layout can differ across environments.

## Regression gate

The regression gate uses packaged datasets and the pinned BGE-small, NLI and reranking models. It can run offline once those models are cached:

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 python -m scinexusrag.eval.gate
```

## Separate answer evaluations

`python -m scinexusrag.eval.generation` compares NLI scores for answers generated by a local Transformers model on a SciFact sample. Its default generator is `Qwen/Qwen2.5-0.5B-Instruct`, not the application's Ollama model. It uses up to four passages truncated to 400 characters and an NLI score to decide whether to use the answer from a PRF retry. This is a model-scored experiment, not a human assessment of correctness. The generator revision is not pinned.

`python -m scinexusrag.eval.ragtruth` scores existing responses from `wandb/RAGTruth-processed`. It uses at most 12 output sentences and 50 context sentences per response. It does not evaluate answers generated by NexusRAG, and its dataset revision is not pinned. No generation or RAGTruth scores are claimed in the README.

See the [README references](../README.md#references) for the retrieval, fusion and dataset papers.
